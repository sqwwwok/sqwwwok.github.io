## 1. [1752vc Pitch Deck Analyzer](https://www.producthunt.com/products/1752vc-pitch-deck-analysis) · [官网](https://1752.ai/)

**标语**：Know what investors will say before you ever hit send.

**背景**  
风险投资机构 1752vc 推出的免费 BP（pitch deck）分析器：上传 PDF（约 25MB / 最多约 30 页）后，用多模态 RAG 对照宣称的 25,000+ 真实 deck 与投资人决策标注，给出可融资度拆解、逐页诊断与红旗提示；官网强调加密传输与存储、无需信用卡，并叙事为「更好信号 → 更容易识别可投项目」。抓取时约 **250** 票、约 **78** 评，日榜第 1。

**产品要解决的问题**  
创始人常在未获真实投资人视角前就把 deck 发出去；朋友反馈偏软、通用 AI 建议空泛，而投资人筛查往往在数分钟内结束且很少给出可执行否决原因。

**产品市场分析**  
目标为筹备融资的早期创始人与加速器项目方。竞品为通用聊天助手、各类 pitch 辅导服务与其他 deck 评分工具。差异化叙事是「VC 自建 + 真实决策语料 + 逐页可融资信号」；变现上工具本身标为免费，上游价值在项目管道与机构品牌（以官网为准）。

**产品上下游**  
上游：创始人导出的 PDF deck（Slides / Keynote / PPT / Figma 等）。下游：可融资评分与红旗清单回流到 deck 改写，优质材料可能进入 1752vc 项目可见度/项目邀请路径。

## 2. [Hy4 preview](https://www.producthunt.com/products/hunyuan-a13b) · [GitHub / 权重](https://github.com/Tencent-Hunyuan/Hy4-preview)

**标语**：Tencent’s 770B open model for long-horizon work

**背景**  
腾讯混元团队开源的 Hy4 preview：约 **770B** 总参、约 **49B** 激活的 MoE 旗舰预览模型，宣称超 **1M** token 上下文，面向编码、办公与科研等长程生产力任务；权重可在 Hugging Face / ModelScope 等获取（含 FP8），也可经 WorkBuddy、CodeBuddy、元宝等产品或 TokenHub / OpenRouter 等 API 接入，并有 vLLM 等部署配方。抓取时约 **180** 票、约 **3** 评，日榜第 2。

**产品要解决的问题**  
开源社区需要能覆盖长上下文、复杂工具调用与工程任务的旗舰权重；闭源 API 难自建，而同等体量开源模型部署与推理栈门槛仍高。

**产品市场分析**  
目标为模型研究者、要自托管推理的平台方，以及通过腾讯生态试用的开发者。竞品为其他开源旗舰（如各类 GLM / Kimi 等开源线）与云端闭源大模型。差异化叙事是「770B MoE + 长上下文 + Apache 系开放权重」；变现跟随腾讯云 API / 产品订阅与生态导流（以官方披露为准）。

**产品上下游**  
上游：预训练/后训练语料、推理框架（vLLM 等）与多卡 GPU。下游：聊天、编程助手与 agent 工作流；权重与部署脚本回流到 Hugging Face 等社区与企业私有部署。

## 3. [Cohere Parse 5](https://www.producthunt.com/products/cohere-2) · [官网](https://cohere.com/parse)

**标语**：Turn complex docs, tables & images into AI-ready data

**背景**  
Cohere 的文档视觉解析能力（Parse）产品化更新：把扫描件、复杂排版、表格与嵌入图转为可检索/可行动的结构化数据，支持 OCR、视觉 grounding（边界框）、多语种，以及云 API、Model Vault、SageMaker、Azure 与私有化部署。公开材料强调高吞吐下的性价比，并可作为 Compass 文档智能栈中的解析环节。抓取时约 **163** 票、约 **4** 评，日榜第 3。

**产品要解决的问题**  
企业知识库与 agent 依赖合同、报表、票据等非结构化文件；通用 OCR/切块常丢掉表格结构与版面依据，大规模解析成本也难预测。

**产品市场分析**  
目标为企业搜索、智能文档处理与 multimodal agent 建设方。竞品为其他文档解析 VLM、传统 IDP 套件与自建 OCR 流水线。差异化叙事是「解析质量 + 页级成本可控 + 企业部署选项」；变现以 API / Model Vault 页费与平台套餐为主（以 Cohere 报价为准）。

**产品上下游**  
上游：PDF/图片等多模态企业文档。下游：结构化块与坐标进入 Embed / Rerank / Compass 检索与 agent 工具调用，回流到索引更新与计费用量。

## 4. [seendiff](https://www.producthunt.com/products/seendiff) · [官网](https://seendiff.com/)

**标语**：Code diff viewer with progress tracking

**背景**  
面向超大变更集的本地 diff 审阅工具：在 git 仓库内启动 localhost 浏览，自动标记已滚过的「seen」、用快捷键标记「reviewed」，带 minimap、跨文件搜索、主题与虚拟化渲染（公开材料称可流畅浏览约 4 万行级文件）；强调无遥测、进度可跨 rebase/amend 持久化，并提供 coding agent walkthrough skill。开源，安装依赖较少。抓取时约 **134** 票、约 **7** 评，日榜第 4。

**产品要解决的问题**  
AI 生成的巨型 PR / 本地大 diff 难在 GitHub UI 或 IDE 里完整审完：容易漏看，也难回答「我到底看过哪些块」。

**产品市场分析**  
目标为审查大变更的开发者与人机协作审阅流程。竞品为 GitHub diff、IDE review 面板与其他本地 diff 工具。差异化叙事是「审阅进度状态机 + 本地隐私 + agent walkthrough」；变现信号以开源工具为主（以项目页为准）。

**产品上下游**  
上游：本地 git 仓库与选定的 base ref。下游：已审标记与可复制的代码引用进入人工合并决策或 agent 讲解笔记；可选 skill 安装回流到 coding agent 工作流。

## 5. [Neo](https://www.producthunt.com/products/neo) · [GitHub](https://github.com/hughhowey/neo)

**标语**：A novel-writing tool from the author of Silo

**背景**  
《Silo》作者 Hugh Howey 打造的分心最小化长篇小说写作器：从书籍结构（书架、手稿呈现）出发，而不是通用办公文档模型；含「Silo」专注模式（全屏、退出需键入指定告白）等偏执设计，强调反臃肿。公开材料称免费、跨平台 Electron 系分发，源码在 GitHub，作者持续按自身写作需求小步迭代。抓取时约 **126** 票、约 **6** 评，日榜第 5。

**产品要解决的问题**  
Word / Pages 等通用编辑器在章节编号、版式与干扰上拖慢长篇小说；功能膨胀的写作套件又常偏离「只写书」这一件事。

**产品市场分析**  
目标为长篇虚构作者与希望极简写作环境的独立写作者。竞品为 Scrivener、Ulysses、Pages 全屏模式等。差异化叙事是「小说家自用、反 feature creep」；变现以免费/开源分发为主（以作者说明为准）。

**产品上下游**  
上游：作者的章节与书架项目文件。下游：可导出的手稿进入编辑/出版流程；反馈经博客评论与 GitHub issue 回流到版本迭代。

## 6. [Cursor Craft v2](https://www.producthunt.com/products/cursor-craft) · [官网](https://cursor-craft.app/)

**标语**：Custom Mac cursors, rebuilt for v2

**背景**  
macOS 自定义鼠标指针应用的第二代：浏览、预览并一键应用成套 cursor pack，界面重做，浏览更快，离线/断网状态更清晰，渲染改进并为后续动态/动画 pack 打基础。应用本身免费，可选高级包为一次买断式内购、无订阅；要求 macOS 13+。抓取时约 **99** 票、约 **7** 评，日榜第 6。

**产品市场分析**

**产品上下游**  
上游：官方/创作者提供的指针素材包与用户设备上的 macOS 光标 API。下游：应用到系统指针后进入日常操作；购买与收藏回流到 Library 与内容更新周报。

## 9. [Mossy](https://www.producthunt.com/products/mossy-2) · [产品页](https://www.producthunt.com/products/mossy-2)

**标语**：A desk plant that wilts when you need a break

**背景**  
寄居在 Mac 桌面上的小植物：久坐不休息就会逐渐蔫掉；用户用一句话描述休息内容（拉伸、俯卧撑、学西班牙语词、站起来等），AI 据此一次生成一项带计时的休息任务。公开 PH 描述强调不遮挡/不降低屏幕亮度、忽略它也是正常用法；免费、无账号、约 **1.4 MB**、原生、macOS 12+。官网直链在本次抓取中未能稳定解析，摘要主要依据 Product Hunt 产品页。抓取时约 **91** 票、约 **11** 评，日榜第 9。

**产品要解决的问题**  
传统休息提醒易变成恼人弹窗或全屏打断；缺少「温柔、可被忽略、但仍有情感反馈」的久坐干预。

**产品市场分析**  
目标为长时间对着 Mac 工作、希望轻量健康提醒的用户。竞品为休息类菜单栏应用、番茄钟与其他桌宠。差异化叙事是「会蔫的桌面植物 + 一句话生成休息任务」；变现以免费分发为主（以产品页为准）。

**产品上下游**  
上游：用户活动/久坐信号与一句休息偏好描述。下游：计时休息任务出现在桌面植物交互中；完成或忽略反馈回流到植物状态与下一次提示。

## 10. [RawToHEIC](https://www.producthunt.com/products/rawtoheic) · [官网](https://rawtoheic.app/)

**标语**：Convert RAW to HEIC inside Apple Photos

**背景**  
在 Apple Photos 内把相机 RAW / iPhone ProRAW 转为 HEIC 的端侧应用（iPhone / iPad / Mac）：宣称体积可显著缩小（示例叙事约 10×），并尽量保留编辑、相册、收藏与元数据；删除原片为可选且需校验写入成功。免费额度约每天 **50** 次转换，无限额约 **$19.99** 买断或 **$9.99**/年，三端一次购买；要求较新的 Apple 系统版本。抓取时约 **77** 票、约 **2** 评，日榜第 10。

**产品要解决的问题**  
RAW 占满本地与 iCloud 空间，但又想保留后期弹性；导出到桌面转换器再导回 Photos 流程重，还易丢编辑与相册关系。

**产品市场分析**  
目标为用 Apple Photos 管理大量 RAW/ProRAW 的摄影用户。竞品为桌面批量转码工具、相机厂商软件与直接删原片。差异化叙事是「Photos 扩展内完成 + 端侧隐私 + 保留库内关系」；变现为免费额度 + 买断/年费（以官网为准）。

**产品上下游**  
上游：Photos 图库中的 RAW/ProRAW（及 iCloud 按需下载）。下游：写入库内的 HEIC（含 HDR gain map 等）同步回设备与 iCloud；空间节省与可选删除回流到拍摄与存档策略。
