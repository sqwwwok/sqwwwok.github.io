## 1. [“I just chose words carefully”](https://unsung.aresluna.org/i-just-chose-words-carefully/)

**背景介绍**  
Unsung / aresluna 短文介绍 1990 年代末 rs1n 为 *Super Metroid* 写的等宽 ASCII 攻略：在等宽字体中做全两端对齐通常只能靠加倍空格或连字符，观感与复制体验都很差；作者选择第三种办法——**精选用词**，让每一行字母数恰好顶满右边界，全文约一万七千词、几乎没有双空格。FAQ 写明「没有用程序做 justify，只是小心选词，在 ASCII 编辑器里完成」。文章将其与实体书排版中为避免孤行/寡行而改写的习惯对照，并联想到 UI 文案为塞进固定宽度而反复打磨。

**主要讨论方向与观点**  
评论多半是共鸣与旁证：有人猜想作者是否故意保留 missle/missile 拼写错误以免整段重排；有人联想到 Gillian Anderson 谈 *X-Files* 编剧 Chris Carter 为脚本版式（避免 widow）改对白节奏；另有人分享用 vim/`fmt` 把注释重排到固定列宽、以及为本地化（如德语更长）和系统缩放导致按钮截断的经历。整体把该攻略读作排版强迫与文字游戏，而非实用工具推荐。

**专有名词解释**  
- **Full justification（两端对齐）**：使左右边距都齐平；等宽环境里通常依赖不均匀空格。  
- **Widow / orphan（孤行/寡行）**：段落首行落在页末、或末行落在页首等版式瑕疵。  
- **Monospace / ASCII art 排版**：每个字符占等宽；适合代码与纯文本，不适合常规印刷级对齐。

## 2. [Creepy Crawlies](https://people.kernel.org/monsieuricon/creepy-crawlies)

**背景介绍**  
Linux 内核基础设施维护者 Konstantin Ryabitsev（monsieuricon）在 people.kernel.org 发文，用数字说明 **git.kernel.org** 上 AI/爬虫负载：约 5 个地理节点、90 核中常有约 14–16 核只在为爬虫渲染 HTML 提交页；合法请求据粗估仅约占流量 2%。内核与邮件列表历史可 `git clone`，却被以「逐 commit 渲染 HTML 再解析」的最笨方式抓取；cgit 可生成海量 URL（含旧 fork、diff、patch）。封禁从 UA → IP → ASN，再到住宅/移动代理 SDK 短命 IP；部署 **Anubis** 工作量证明后一度有效，但难度从 4 提到 5 后，仍有约三分之一请求解出挑战进入站点。团队正关闭部分匿名可爬功能，同时承诺数据仍可下载，只是门槛更高。

**主要讨论方向与观点**  
讨论极热。技术批评集中在 Anubis 经济学：有人在 iPhone 上写加速扩展，用 ARM SHA 指令把高难度 PoW 压到毫秒级，并指出 ASIC 算力远超手机，**PoW 更伤真人、难挡专业爬虫**；tptacek 引用 Tavis Ormandy 一年前的类似判断。另有人分享 iocaine 式「蜜罐黑洞」、假数据/慢字节响应；亦有人指出 cookie 复用可绕过重复 PoW。运营者共鸣：小站点也遭无脑全链爬取；代理 SDK 与家电设备成攻击面。共识偏向「没有简单解」，公开镜像仍可能被迫加门槛。

**专有名词解释**  
- **cgit**：用 CGI 把 git 仓库渲染成可浏览网页的常见方案。  
- **Anubis**：面向爬虫的浏览器端 PoW 挑战中间件。  
- **Proxy SDK monetization**：应用/设备把住宅 IP 卖给爬虫代理网络的商业模式。  
- **ASN**：自治系统号；常用于按云厂商网段批量封禁。

## 3. [Haiku R1/beta6 has been released](https://www.haiku-os.org/news/2026-08-26_haiku_r1_beta6)

**背景介绍**  
开源桌面操作系统 **Haiku**（BeOS 精神继承者）发布 **R1/beta6**：距上一 beta 约两年，且紧挨项目 25 周年。发布说明称本周期解决逾 530 项缺陷/增强；系统仍为 beta，不承诺无数据丢失。亮点包括：HaikuDepot 上出现获 Mozilla 官方 branding 许可的 **Firefox** 及 LibreWolf、Waterfox、Floorp、Icedove 等；x86_64 上为 QEMU 引入源自 NetBSD 的 **NVMM** 硬件虚拟化加速；Go 等更多软件移植；以及 MIME sniff、字符串哈希、内核锁粒度、FIFO/`pipe()` 吞吐、库函数与 `malloc` 等大量性能优化。平台提供 32/64 位 x86 镜像，强调一作组件不使用 AI 生成代码。

**主要讨论方向与观点**  
支持者称赞视觉与「工具型 OS」气质，相对主流桌面的遥测/订阅文化；亦有人实测旧 ThinkPad 上 beta6 启动回退（ACPI、USB Audio 与 Focusrite 等），需安全模式。有人认为 Linux 已足够轻量且有容器，Haiku 失去轻量优势；另有人期待低延迟音频/MIDI 工作流，或受无障碍栈缺失限制。讨论气氛以庆祝发布与稳定性期待为主。

**专有名词解释**  
- **Haiku / BeOS**：Haiku 旨在兼容并延续 BeOS 的个人计算桌面理念。  
- **NVMM**：NetBSD Virtual Machine Monitor，为 QEMU 提供硬件虚拟化后端。  
- **HaikuDepot / HaikuPorts**：官方包仓库与社区移植项目。

## 4. [Cores in space: The core memory module from a 1980 Spacelab computer](https://www.righto.com/2026/08/spacelab-core-memory.html)

**背景介绍**  
Ken Shirriff（righto）拆解 **Spacelab**（航天飞机货舱可复用加压实验室）所用法国 **Mitra 125 MS** 小型机的磁芯内存：约 128 KB RAM，由铁氧体磁环按位存储，而非硅 DRAM。文章回顾 coincident-current 选址、滞后特性、破坏性读出与 rewrite、sense/inhibit 线、二极管矩阵，以及为何 1980 年仍在航天场景使用高密度磁芯（非易失、抗辐射等历史语境）。该机为 16 位字宽，另加奇偶与 storage-protect 位共 18 位/字；三台相同计算机分别管理舱段、实验与备份。文中含大量实物照片与原理图。

**主要讨论方向与观点**  
评论以技术追问与赞叹为主：作者本人现身答疑；有人讨论多芯堆叠是否为减少 sense amp、对比现代重量；另有人把航天 **N-modular redundancy** 联想到用多语言 LLM 实现投票容错的设想。整体偏硬件考古与科普，争论不多。

**专有名词解释**  
- **Magnetic core memory（磁芯内存）**：用磁环磁化方向存 0/1 的主存技术，约在 1970 年代被半导体内存取代。  
- **Coincident current addressing**：X/Y 半选电流在交叉点叠加翻转目标磁芯。  
- **Spacelab / Mitra 125 MS**：欧方航天实验室与其法国制控制计算机。

## 5. [Show HN: NFC Energy-Harvesting PCB Business Card with an MCU](https://wilsonharper.net/projects/businesscard/)

**背景介绍**  
Wilson Harper 的 Show HN：信用卡厚度的 **PCB 名片**，无电池；手机 NFC 近场供电即可驱动 MCU 与约 21 颗 LED 动画，并可通过 NFC 传递联系信息。设计使用 NXP **NTAG I2C Plus** 能量采集输出、**ATtiny816**、Charlieplexing 驱动多 LED，并处理 VOUT 电容启动限制（限流电阻 + MOSFET 迟滞接入大电容）。天线按约 2.75 µH / 13.56 MHz 调谐；布局刻意避免铜环形成涡流破坏 NFC。JLCPCB 组装、RoHS/ENIG；用 Pico/UPDI 烧录，NTAG 用 NXP TagWriter 写入。作者强调可批量赠送的成本与工程学习路径，仓库开源。

**主要讨论方向与观点**  
评论量不大，偏玩梗与功能脑洞：有人引用「能量调制回传」机制联想快递签收场景；有人想要压电蜂鸣器播放拨号音；另有人希望可定制小批量套装，或吐槽钱包里已有太多 NFC 标签互扰。整体认可为「认真的小工程」而非商业产品发布。

**专有名词解释**  
- **NFC energy harvesting**：从 13.56 MHz 近场耦合取电驱动外部电路。  
- **Charlieplexing**：用三态 GPIO 与二极管单向特性，以较少引脚驱动较多 LED。  
- **UPDI**：Microchip AVR 单线调试/编程接口。

## 6. [Sort branches by last commit date](https://ryangreenberg.com/til/git-branches-by-commit-date/)

**背景介绍**  
Ryan Greenberg 的 TIL：多年用 shell 循环 `git branch` + `git log` 再 `sort` 查看最近分支后，发现现代 Git 可直接配置  
`git config branch.sort committerdate`  
或一次性 `git branch --sort=committerdate`。排序键与 `git for-each-ref` 相同，文中列举 `authordate`、`creatordate`、`contents:size`、`upstream` 等可选项。

**主要讨论方向与观点**  
实用向补充占主导：有人推荐前置 `-` 实现最新在前（`branch.sort -committerdate`）；有人建议再接 **fzf**，或使用 paulirish 的 `git recent`；Fish 用户称补全已按最近提交排序。另有人吐槽默认字母序对分支坟场毫无帮助。几乎无争议。

**专有名词解释**  
- **`git for-each-ref`**：枚举/格式化/排序 refs 的底层命令；`git branch --sort` 复用其键。  
- **committerdate / authordate**：提交者时间与作者时间，可能因 rebase/amend 不同。  
- **fzf**：模糊查找选择器，常用于交互选分支。

## 7. [Continuous Diffusion Language Models (CDLM's)](https://sander.ai/2026/08/24/continuous-dlms.html)

**背景介绍**  
DeepMind 研究者 Sander Dieleman 长文回顾 **连续扩散语言模型（CDLM）**：相对自回归逐 token，扩散通过逐步去噪生成；2021 年离散扩散（D3PM 等）兴起，2022 年出现把 token 嵌入连续空间再加高斯噪声的路线（Diffusion-LM、SED、CDCD 等），但 2023 末后连续路线近乎「灭绝」，研究转向离散扩散以追赶 LLM 性能。文中讨论嵌入策略、损失、噪声日程与 **self-conditioning**，并分析训练效率差距（如 Plaid 一度被报约 64×）如何与 ChatGPT 后「拼性能」风气叠加。作者称近期连续方法又有回潮迹象，文中给出主观史观与技术更新（抓取正文覆盖历史与方法部分；后文细节以原文为准）。

**主要讨论方向与观点**  
有评论反驳「2020/21 自回归尚未确立」的叙述，强调 GPT-2/3 与后来 **RLHF/DPO 后训练** 才是对话产品分水岭，并认为在自回归上叠加扩散会更难工程化。另有人肯定非 AI 生成的技术写作，并对扩散语言的创意潜力表示期待。讨论量相对不高，偏专业读者。

**专有名词解释**  
- **Autoregressive LM**：按位置条件预测下一 token 的主流 LLM 范式。  
- **CDLM / DDLM**：连续 vs 离散扩散语言模型。  
- **Teacher forcing**：训练时用真值上文而非模型自身采样，可能导致 exposure bias。  
- **Self-conditioning**：把模型先前预测再喂回以稳住连续扩散训练/采样。

## 8. [Why open source rocks – a new SM750 (Silicon Motion GPU) HDMI Driver](https://github.com/KodeMunkie/sm750hdmifb)

**背景介绍**  
GitHub 项目 **sm750hdmifb**：面向特定廉价 PCIe 卡（SE-DP750A-HDMI，Silicon Motion **SM750** + SiI9024 HDMI 发送器、16 MiB 显存、PCI ID `126f:0750`）的实验性 Linux **DRM** 驱动。作者（Show 文）称购卡本想让 NVIDIA 只做计算、用小卡跑 X11，但主线 `sm750` 主要覆盖旧 VGA/DVI 变体；于是「vibe code」新驱动，支持更高分辨率/刷新（含经 dither 的超宽尝试）、RGB565 扫描以缓解 PCIe 1.1 x1 带宽，并含自研 ordered dither（bbdither）。面向 Linux 6.17+，提供 DKMS 包，需黑名单旧 `sm750fb`。仓库明确警告非 EDID/超规格模式可能导致无信号，需保留 SSH 等恢复手段。

**主要讨论方向与观点**  
作者置顶说明动机与迭代；有人追问 vibe coding 的调试闭环；另有人惊叹「HDMI + 仅 16MB VRAM」组合，或建议列入 FSF RYF 硬件关注列表。亦有「如今还有无核显主板吗」的吐槽。基调是开源让冷门硬件起死回生。

**专有名词解释**  
- **DRM（Direct Rendering Manager）**：Linux 内核图形子系统接口。  
- **DKMS**：按当前内核头文件自动重编译外树模块的打包方式。  
- **EDID**：显示器告知主机的分辨率/时序能力数据。  
- **Ordered dither**：用固定阈值把较高色深近似到较低色深（此处配合 RGB565）。

## 10. [Commercially Available Bike Generators Are Not Sustainable (2011)](https://solar.lowtechmagazine.com/2011/05/bike-powered-electricity-generators-are-not-sustainable/)

**背景介绍**  
Low-tech Magazine 2011 年文章（标题已标年份）：批评市售「把公路车架在训练台上发电+电池」方案。作者估算电机/发电机、调压、电池与逆变等环节合计损耗约 42–67.5%，再加摩擦传动、赛车姿势与缺飞轮等因素，用电驱动设备往往比机械直驱费力 2–3 倍；铅酸电池 embodied energy 可能需数百小时踩踏才能「赚回」，使所谓绿色发电在生命周期上可疑。主张更应发展为具体任务设计的机械脚踏设备，而非通用自行车发电机套件。文中数据与厂商例证均针对约 2011 年语境。

**主要讨论方向与观点**  
2026 年读者强调时代错位：有人认为便宜光伏+电池已使固定脚踏发电基本多余；有人指出摩擦传动等段落过时，标题应更醒目标 2011。另有人转向「脚控但不靠脚发电」的无障碍/遥控割草等需求，或分享体验：出力大、得电少，不如移动电源。讨论把旧文当作能效直觉教材，而非现行采购指南。

**专有名词解释**  
- **Embodied energy（蕴含能量）**：制造产品所消耗的全生命周期能量。  
- **Friction drive**：轮子压在发电机滚轮上的传动，效率通常低于链/皮带。  
- **Flywheel（飞轮）**：用转动惯量平滑曲柄死点，提高稳态输出。
